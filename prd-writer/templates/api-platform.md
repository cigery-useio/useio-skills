## 7. API 设计规范 [专项]

### 7.1 设计原则

- **RESTful 优先**：遵循 REST 架构风格，资源导向设计
- **命名规范**：URL 使用 kebab-case，字段名使用 camelCase 或 snake_case（择一统一）
- **HTTP 方法语义**：GET 查询 / POST 创建 / PUT 全量更新 / PATCH 部分更新 / DELETE 删除
- **无状态**：每个请求包含所有必要信息，服务端不保存会话状态

### 7.2 URL 规范

```
基础路径：/api/v{version}/{resource}
示例：
  GET    /api/v1/orders              # 查询订单列表
  POST   /api/v1/orders              # 创建订单
  GET    /api/v1/orders/{id}         # 查询订单详情
  PUT    /api/v1/orders/{id}         # 更新订单
  DELETE /api/v1/orders/{id}         # 删除订单
```

### 7.3 请求与响应规范

**统一响应格式**：
```json
{
  "code": 0,           // 0 表示成功，非 0 表示错误
  "message": "success", // 描述信息
  "data": {},           // 业务数据
  "requestId": "uuid"   // 请求追踪 ID
}
```

**分页规范**：
```json
{
  "data": {
    "list": [],
    "total": 100,
    "page": 1,
    "pageSize": 20
  }
}
```

### 7.4 错误码规范

| 错误码范围 | 含义 | 示例 |
|-----------|------|------|
| 0 | 成功 | |
| 1000-1999 | 通用错误（参数/认证/权限） | 1001: 参数校验失败 |
| 2000-2999 | 用户相关错误 | 2001: 用户不存在 |
| 3000-3999 | [业务模块 A] 错误 | |
| 4000-4999 | [业务模块 B] 错误 | |
| 5000-5999 | 系统错误 | 5001: 服务不可用 |
